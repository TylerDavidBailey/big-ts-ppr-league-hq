# CLAUDE.md

Guidance for Claude Code working in this repository.

## What this is

A static React site on GitHub Pages for one fantasy football league, Big-T's PPR League.
It shows the playoff podium, the paid season awards with their money, the weekly beer duty,
standings and derived stats, and all-time standings and records across every season.

There is no backend, no database, no API key, and no build-time secret. The browser calls
Sleeper's public read-only API directly.

The league id, the money, and the rule text live in `src/league.config.ts` and nowhere
else. Every number on the site comes from Sleeper. A new season needs no edit:
`src/lib/sleeper/head.ts` finds it through a manager's league list.

## Commands

Use the Makefile. `make` on its own lists every target.

```bash
make check      # lint, format check, typecheck, unit tests, build, browser tests
make check-fast # the same, without the browser tests. Use while iterating
make fix        # auto-fix lint findings and reformat
make test       # unit tests once
make e2e        # browser tests against mocked Sleeper responses
make e2e-live   # browser tests against the real API. Run after touching src/lib/sleeper/
make shots      # full-page screenshots of every state, desktop and phone, into screenshots/
make shots-live # the same set from the real API
make up         # dev server in the background at http://localhost:5173/
make down       # stop it
make players    # regenerate public/data/players.min.json from Sleeper
```

`make check` runs exactly what CI runs, in the same order.

## Rules that break things when ignored

**`src/domain/` must not import from `features/`, `app/`, or `components/`.** The domain
layer is pure: no React, no `fetch`, no globals. That boundary is what lets the league logic
be tested from captured JSON.

**Money and rule text come from `src/league.config.ts` only.** Never hardcode a dollar
amount or an award name in a component or in the domain layer.

**Seasons link backwards only.** `previous_league_id` finds older seasons. Newer ones come
from `GET /user/{id}/leagues/nfl/{season}`, which `resolveHead` asks for when the configured
league is `complete`. Never assume the config id is the newest season.

**Never call `GET /players/nfl` from the browser.** It is 14.6 MB. Player names come from
`public/data/players.min.json`, generated by `scripts/build-player-index.mjs` and refreshed
weekly by `.github/workflows/refresh-players.yml`.

**Never hardcode week 14.** The regular season ends at
`league.settings.playoff_week_start - 1`. Read `season.regularSeasonEndWeek`, or iterate
`season.regularSeasonWeeks`, which is already filtered.

**Iterate `season.regularSeasonWeeks`, never `season.weeks`, in an award or a stat.** It
excludes the week currently being played. Sleeper posts scores from Thursday night, so a
live week has most rosters near zero; settling a record or a punishment on it names the
wrong team from Thursday until Sunday evening.

**Every award is a ranked list, and a tie shares a place.** `rankPlaces` in
`src/domain/awards.ts` assigns competition places and marks ties. Never pick one winner
with `>` or `<` alone, or the award silently goes to the lowest roster id. The same applies
to standings: `StandingsRow.tied` marks an order that is arbitrary.

**Match managers across seasons by Sleeper user id, never by roster id or handle.**
Roster numbers repeat every season and handles get renamed. `managerKey` in
`src/domain/history.ts` is the one place that decides identity; an unclaimed roster is
keyed by league and roster so two years never merge.

**A cross-season tally must not credit a live season with a title or a 1 seed.** Check
`season.isRegularSeasonComplete` before counting a 1 seed, and read titles from the
bracket's placement games only.

**Sleeper's `fpts` and `ppts` are regular-season totals.** Verified against the live API:
they cover weeks 1 through `playoff_week_start - 1` and nothing after. That is why
lineup efficiency can divide one by the other with no lineup solver.

**A median-scoring league (`league_average_match: 1`) cannot be scored from matchups.**
Sleeper adds a second result each week against the league median, which is absent from the
matchup data. `buildSeason` falls back to Sleeper's reported roster totals and sets
`usesMedianScoring` so the UI can say so.

**An unplayed week is `[]` under HTTP 200. A missing league is `null` under HTTP 404.**
Conflating them breaks both the empty state and the error state.

**Points are split into two integers.** `fpts + fpts_decimal / 100`. The same applies to
`fpts_against` and `ppts`.

**`metadata.team_name` is often absent.** Fall back to the user's `display_name`.

More of these are recorded in [docs/sleeper-api.md](docs/sleeper-api.md). Read it before
adding an endpoint.

## Layout

```
src/
	league.config.ts  the league id, money, and rule text
	app/              providers, router, error boundary, query client
	components/       UI primitives and site chrome
	domain/           pure league logic
		buildSeason.ts  raw Sleeper JSON to one SeasonModel
		awards.ts       the four awards as ranked lists
		stats.ts        power rankings, lineup efficiency, superlatives
		history.ts      all-time standings, records, champions
	features/         the page shell, the season views, the all-time views
	lib/              Sleeper client, one-query-per-season fetch, player index, formatting
	styles/           the Tailwind theme
	test/             setup and captured fixtures
```

`src/domain/buildSeason.ts` is the centre. It turns raw Sleeper JSON into one `SeasonModel`
that every view, every award, and every stat reads.

## Tests

Vitest with jsdom. Tests sit next to the code as `*.test.ts`.

Fixtures in `src/test/fixtures/` are real Sleeper responses from this league's finished
2025 season, captured by `scripts/capture-fixtures.mjs` and anonymised by
`scripts/anonymize-fixtures.mjs` on the way in. Handles, user ids, avatars, the league name,
and league-chat fields are synthetic; every number is real. Assert on numbers, and read ids
from the fixture rather than hardcoding them. `make fixtures` re-captures.

Never commit a fixture that bypasses the anonymiser.

`src/domain/**` has a 90% coverage threshold. New league logic needs a test.

Browser tests live in `e2e/`. `app.spec.ts` mocks every Sleeper request from the same
fixtures and runs in CI. It serves the configured league id as a 2026 pre-draft season
chained to the fixture's 2025 season. `live.spec.ts` is tagged `@live`, hits the real API,
and runs only through `make e2e-live`.

## Styling

The palette in `src/styles/theme.css` comes from Sleeper's own production stylesheet, so the
app matches their UI. Change a semantic alias such as `--color-brand`, not a raw hex value.

Fonts are Inter and Oswald, self-hosted through `@fontsource`. Oswald stands in for Sleeper's
proprietary Druk Condensed.

## Conventions

Branches are `<type>/<description>`. Commits follow Conventional Commits:
`<type>(<scope>): <description>`.

Prose in this repo, including commit messages and PR descriptions, avoids em dashes and AI
vocabulary. Sentence case headings. Straight quotes.

## Verifying a change by hand

Nine routes cover the states that matter. Run `make up` and open each one.

- `/` is the newest season's overview. While it is pre-draft, it shows the rules, the
  payouts, three empty podium slots, and the managers.
- `#/2025` is a finished season's overview: the podium, each award's winner, the beer duty
  leader, and the playoff seeds.
- `#/2025/awards` has five places on every award card.
- `#/2025/beer-duty` has 14 weeks and the season tally.
- `#/2025/standings` has the table and the power rankings.
- `#/2025/stats` has the superlatives and lineup efficiency.
- `#/2025/rules` has the payouts and the season format.
- `#/all-time` has one row per manager.
- `#/all-time/champions` has a row for every season; `#/all-time/records` the record book.

The in-season state has no live league to open. `e2e/fixtures.ts` fakes one with the
`liveWeek` option, which the browser tests use.

`make shots` captures every one of these states, plus the error and not-found pages, at
1280 and 390 wide into `screenshots/`. Look at them after a layout change.
